## Python Level 1 – Professional Course

**Goal**: Transform a complete beginner into a job-ready, production-oriented Python developer while fully covering and deepening the PCEP-30-02 syllabus and preparing for PCAP.

This repository contains the full curriculum assets for the **Python Level 1 Professional Course**, including:

- **curriculum**: high-level roadmap, skills progression, and alignment with PCEP.
- **modules**: detailed teaching plans, learning objectives, and lesson structures.
- **projects**: 10 progressively challenging mini projects.
- **capstones**: 2 major capstone projects that simulate real-world work.
- **assignments**: structured weekly/lesson practice sheets.
- **assessments**: rubrics and evaluation frameworks.
- **resources**: reference material, checklists, and workflow guides.

The course is designed for:

- Learners who are new to programming but serious about professional development.
- Self-taught developers who want rigorous structure and PCEP/PCAP alignment.
- Teams who want an internal Python onboarding path with strong engineering practices.

### Course Outcomes

By the end of Level 1, a diligent student will be able to:

- **Write clean, PEP 8–compliant Python code** using functions, control flow, and core data structures.
- **Build small but realistic CLI applications** with input validation, logging, and basic configuration.
- **Work effectively with Git** for version control, feature development, and code review.
- **Apply defensive programming and error-handling patterns** using Python’s exception mechanisms.
- **Organize code into modules and small systems** that are testable and maintainable.
- **Confidently attempt the PCEP exam** and be well prepared to step into PCAP-level topics (OOP, modules, more advanced standard library features).

### Repository Structure

- `curriculum/`
  - High-level roadmap and alignment docs.
- `modules/`
  - One subfolder per teaching module, each with a detailed `MODULE.md`.
- `projects/`
  - One subfolder per mini project, each with a detailed project spec.
- `capstones/`
  - One subfolder per capstone, each with problem statement, architecture, and roadmap.
- `assignments/`
  - Weekly/module practice sheets linked to modules and projects.
- `assessments/`
  - Rubrics for code style, mini projects, capstones, quizzes, and practical exams.
- `resources/`
  - Supplemental reading, code review checklists, and Git workflow guidance.

### Usage Modes

- **Instructor-led cohort**
  - Use `curriculum/` and `modules/` to plan sessions.
  - Use `assignments/` and `assessments/` for weekly work and grading.
  - Use `projects/` and `capstones/` as the backbone of hands-on learning.

- **Self-paced learner**
  - Start with `curriculum/ROADMAP.md` to understand the journey.
  - Progress through `modules/` in order, implementing the linked mini projects.
  - Use the rubrics in `assessments/` as self-review checklists.

### Professional Principles Embedded

Throughout the course, learners will be expected to:

- Follow **PEP 8** and agreed naming conventions from day one.
- Use **Git** for all significant work (feature branches, clear commit messages).
- Think in terms of **separation of concerns** and modular design.
- Prefer **logging** over ad-hoc `print` statements for operational visibility.
- Write **defensive, validated input paths** rather than trusting user input.
- Incrementally **refactor** code toward cleaner designs as knowledge grows.

For a high-level narrative of the course, see `curriculum/ROADMAP.md`.
