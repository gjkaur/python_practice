# Final Capstone Evaluation – Week 12

**Focus**: Integration of all PCPP sections  
**Duration**: Ongoing (Weeks 8–12)  
**Weight**: 40% of course grade

## Overview

The final evaluation consists of two capstone projects that integrate multiple PCPP sections:

1. **Capstone 1**: Full-Stack GUI Application with Database
2. **Capstone 2**: REST Client with GUI Frontend

## Evaluation Timeline

- **Week 8**: Project proposals due
- **Week 9**: Progress check-in
- **Week 10**: Mid-development review
- **Week 11**: Final review and feedback
- **Week 12**: Final submission and presentation

## Capstone 1: Full-Stack GUI Application

### Requirements

- GUI application using tkinter (PCPP 3.1–3.3)
- SQLite database backend (PCPP 5.1)
- Proper OOP design with classes and inheritance (PCPP 1.1–1.8)
- Error handling with chained exceptions (PCPP 1.9)
- Logging system (PCPP 5.2)
- Configuration management (PCPP 5.2)
- Code quality: PEP 8, PEP 257, PEP 484 (PCPP 2.1–2.3)

### Evaluation Criteria

- **Functionality (25%)**: All features work correctly
- **Architecture (20%)**: Proper separation of concerns (GUI/services/database)
- **OOP Design (15%)**: Advanced OOP features used appropriately
- **Code Quality (15%)**: PEP 8/257/484 compliance
- **Error Handling & Logging (10%)**: Comprehensive and user-friendly
- **Testing (10%)**: Unit tests for core logic
- **Documentation (5%)**: README and code documentation

## Capstone 2: REST Client with GUI Frontend

### Requirements

- REST API client using `requests` (PCPP 4.1–4.4)
- GUI frontend using tkinter (PCPP 3.1–3.3)
- JSON/XML processing (PCPP 4.3)
- Data persistence (shelve or SQLite) (PCPP 1.11, 5.1)
- Error handling and logging (PCPP 1.9, 5.2)
- Configuration management (PCPP 5.2)
- Code quality: PEP 8, PEP 257, PEP 484 (PCPP 2.1–2.3)

### Evaluation Criteria

- **Functionality (25%)**: REST client works with real APIs
- **GUI Design (15%)**: User-friendly interface
- **Network Programming (15%)**: Proper use of requests, error handling
- **Architecture (15%)**: Clean separation of concerns
- **Code Quality (15%)**: PEP 8/257/484 compliance
- **Error Handling (10%)**: Network errors handled gracefully
- **Documentation (5%)**: README and code documentation

## Submission Requirements

Each capstone must include:

1. **Source Code**: All Python files with proper structure
2. **README.md**: 
   - Project description
   - Installation instructions
   - Usage guide
   - Architecture overview
   - PCPP objectives covered
3. **Tests**: Unit tests for core functionality
4. **Documentation**: Docstrings for all public APIs
5. **Git History**: Meaningful commit history showing development process

## Presentation (Optional but Encouraged)

Prepare a 10-minute presentation covering:

- Problem statement and solution
- Architecture and design decisions
- Key features demonstration
- Challenges faced and solutions
- PCPP concepts applied
- Future improvements

## Grading Rubric

See `LEVEL3_RUBRICS.md` for detailed scoring:

- **90–100**: Excellent – Production-ready code
- **75–89**: Strong – Solid implementation with minor improvements needed
- **60–74**: Adequate – Meets requirements but with notable weaknesses
- **<60**: Incomplete or significantly flawed

## PCPP Objective Coverage

Both capstones must demonstrate coverage of:

- **Section 1**: Advanced OOP (at least 6 objectives)
- **Section 2**: PEP Standards (all 3 objectives)
- **Section 3**: GUI Programming (all 3 objectives)
- **Section 4**: Network Programming (at least 3 objectives)
- **Section 5**: File Processing (at least 2 objectives)
