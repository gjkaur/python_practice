# Module 8 – PEP Standards & Best Practices

**PCPP Objectives**: 2.1, 2.2, 2.3

## Learning Objectives

- Understand PEP concepts and Python philosophy (PEP 20)
- Apply PEP 8 guidelines comprehensively
- Write proper docstrings following PEP 257
- Use type hints (PEP 484) effectively
- Use code quality tools (flake8, black, mypy)

## Topics Covered

### Lesson 8.1 – PEP Concepts and Python Philosophy
- PEP: Python Enhancement Proposal
- PEP 1: Purpose, types of PEPs (standards track, informational, process), formats, and guidelines
- PEP 20: "The Zen of Python" (`import this`)

### Lesson 8.2 – PEP 8 Guidelines
- Code layout: indentation, continuation lines, maximum line length, line breaks, blank lines
- Default encodings: UTF-8 is the default; use encoding declaration if needed (e.g. `# -*- coding: utf-8 -*-`)
- Imports: organization and style
- Naming conventions
- Programming recommendations

### Lesson 8.3 – PEP 8 Tooling
- `flake8`: Style checker
- `black`: Code formatter
- `pylint`: Comprehensive linter
- IDE integration

### Lesson 8.4 – PEP 257 Docstrings and Type Hints
- Docstring conventions (PEP 257)
- One-line vs multi-line docstrings
- Type hints (PEP 484)
- Using `mypy` for type checking

## Key Concepts

- **PEP 20**: Python's design philosophy ("Beautiful is better than ugly", etc.)
- **PEP 8**: Style guide for Python code
- **PEP 257**: Docstring conventions
- **PEP 484**: Type hints for function annotations
